## 决策与排查

- **脚本宿主**：本机只有 Windows PowerShell 5.1，没有 `pwsh`。门禁必须在默认 shell 下可运行，
  因此选择"修复脚本"而不是"要求安装 PowerShell 7"。修复方式（BOM、显式 UTF-8 读取、
  跨宿主哈希 API）都不改变脚本语义。
- **桌面自检的边界**：只断言可客观判定的行为（控件存在、状态文本、落库、进程退出），
  不断言外观与文案是否易懂——那部分留在人工验收。密码框没有 ValuePattern，
  该脚本因此不测试输入密钥，也没有改为注入按键：注入按键会打到当时持有焦点的任意窗口。
- **引导下载卡住**：第一次干净工作区验证在 264 MB / 300 MB 处停止推进。交替排除后
  定位为 5.1 的进度条渲染（输出被重定向到文件时尤甚），而非网络或哈希校验问题。
  失败证据保留在 `artifacts/clean-workspace/hang-20261013-2000.log` 与被截断的 `sdk.zip`
  （264110080 / 300608304 字节）。原脚本的 SHA-512 校验能拦下截断文件而不会解压出错包，
  该保护保留。
- **未复现的历史不一致**：TURN-20261013-002 称 `verify.ps1` 已通过，但同一命令在本轮
  起初失败于脚本解析。上一轮的宿主环境无法复现，原因不明；该不一致在 TURN-002 的
  恢复说明中如实保留，未作推测性解释。

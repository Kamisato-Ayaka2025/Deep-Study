## 修改与原因

上一轮只完成了机制探针（ADR-002 的测量 A–G），生产 Runner 仍拒绝执行。本轮把机制落成产品路径，并把攻击矩阵、停止与整树回收、人工入口补齐。

**隔离与执行（`src/StudyHarness.Runner/`）**

- `Sandbox.cs`：标准 AppContainer + Job Object 的生产实现（`SandboxProfile` / `SandboxedProcess`）。
- `RunSession.cs`：一次运行的编译与执行；17 条越界/断网用例逐条判定；`Stop()` 改为返回“本次调用是否写出终态帧”。
- `Junction.cs`（新增）：用重解析点（tag `0xA0000003`，`FSCTL_SET_REPARSE_POINT`）创建真实 junction，用于“运行目录内指向外部的链接”这一逃逸形状。
- `ToolchainDiscovery.cs`：MSVC 链接行补 `advapi32.lib`（MinGW 默认链接，MSVC 不链接，漏掉是 `LNK2019`）。
- `Program.cs`：新增 `--toolchains` 发现报告供门禁使用；`StopRun` 对已结束的运行也给出终态回复。

**宿主与契约（`src/StudyHarness.Application/`、`Contracts/`、`Infrastructure/`）**

- `RunnerPort.cs`（新增）、`RunnerMessages.cs`（新增）：`IRunnerPort`/`IRunnerSession` 与 `RunnerRequest`/`RunnerReply` 线格式、`RunnerResources` 登记集合，按 `Plan.md` §5.5。
- `RunnerHost.cs`（新增）：宿主为管道服务端、当前会话随机握手秘密经继承 stdin 传递、作业 `KILL_ON_JOB_CLOSE`；停止等待加 30 秒上界；数据根规范为绝对路径。

**夹具与测试**

- `fixtures/runner/bundles/{hello,escape,loop}`：固定、可复核的合成夹具，覆盖正例、攻击矩阵与永不终止的程序。
- `tests/StudyHarness.Tests/Runner/{RunnerSmokeTests,RunnerIsolationTests,RunnerStopTests,RunnerProtocolTests,RunnerTestEnvironment}.cs`、`Contracts/RunnerContractTests.cs`。
- `tests/StudyHarness.HostProbe/`（新增）：异常死亡检查所需的第二个宿主进程，以及 `ManualHarness.cs`（人工验收时由人操作的验证程序，驱动生产宿主）。

**脚本与文档**

- `scripts/verify.ps1`：新增 `-Phase P1`（多一步 `toolchains` 发现检查）、`blocked` 状态计入失败、测试同时输出详细控制台日志（把逐用例原始错误号写进 `tests.log`）。
- `scripts/manual-p1.ps1`（新增）：人工验收入口，只做工具链确认、启动验证程序、报告遗留进程。
- `docs/adr/ADR-002`（新增后更新）：补测量 H（生产复测）与实现事实；`docs/acceptance/P1.md`（新增）；`docs/implementation-status.md`、`AGENTS.md`、`INDEX.md`。

**过程中修掉的缺陷**（都会伪装成“隔离策略失败”，故逐条记录）：被杀的 Runner 遗留 AppContainer profile 导致后续创建失败（改为按名沿用同一 SID）；已结束的运行收到 `StopRun` 时只清理不回复，宿主会永远等一个终态帧；作业基线进程数不是常数（Windows 可能为 Runner 启动 `conhost.exe`）；`swprintf` 的 `%s` 在 C99 下是窄字符串，MinGW 把路径截成 `C` 使子进程启动失败（改用 `%ls`）；`Directory.CreateSymbolicLink` 需要本机没有的特权（改用 junction）；UDP 被策略丢弃时 `sendto` 仍返回 0（改在接收端判定）；相对数据根使宿主与 Runner 解析出不同目录（规范为绝对路径）；人工验证程序若切换控制台输出编码会与父进程 PowerShell 冲突（不切换，双方沿用控制台默认编码）。

## 契约与数据影响

- 线协议：`RunnerProtocol.Version = 1`、`SchemaVersion = 1`，与 `Plan.md` §5.5 一致；只承载登记资源 ID（profile/仓库/工具链/测试套件/用途），不承载命令字符串、任意路径或环境变量。
- 数据：无 SQLite 迁移，`user_version` 仍为 2；运行产物写在 `STUDYHARNESS_DATA_ROOT` 下的 `runs/<runId>/`，不进入源码树。P0 的数据契约不变，旧配置继续可用。
- 安全不变式：隔离不可用时 `ISOLATION_UNAVAILABLE` 拒绝执行，不降级为普通进程；密钥仍只走 DPAPI，DTO 不携带密钥值；回复只带稳定错误码与原始 Win32/Winsock 数字，不带异常文本、路径、提示或模型输出。
- 桌面程序仍不执行任何用户代码：Runner 只编译并运行已登记的固定夹具，学习闭环属后续阶段。

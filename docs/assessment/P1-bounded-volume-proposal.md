# P1 磁盘硬上限候选：专用固定容量卷

状态：2026-10-16 用户已明确接受专用定容盘及管理员准备/挂载。实现和实测进行中，证据见TURN-20261016-002；未据此判定P1通过。

最新结果：镜像和NTFS卷已创建，镜像设备权限修复后普通用户可准备目录；但PSEC内MSVC/MinGW读取授权源码失败，目录挂载、卷GUID、盘符及额外卷根只读对照均未解决，填盘阶段尚未到达。相似未解决上游问题见[MXC #1473](https://github.com/microsoft/mxc/issues/1473)，不据此断言完全同因。该方案当前不可接入真实代码路径，不能将“成功挂载”视为容量门禁通过。

## 问题与候选

标准输出已增加管道共享64KiB上限，但PSEC允许实验在work内自行创建任意文件，仍可能耗尽宿主磁盘。目录扫描并杀进程存在扫描间隔，不是硬配额。

候选为固定分配2GiB的专用VHD，单个实验占用该卷、只允许一个活动实验。镜像与宿主控制数据保存在PSEC可写目录之外；只有已核验卷内的work可写。固定容量卷满后写入失败，不扩大镜像，不回退普通宿主目录。历史保留策略必须同时限定总占用，不能每次运行无限新增镜像。默认不复制整卷内容回宿主，不在普通宿主磁盘上递归清理不可信产物。

## 部署和安全约束

创建/挂载走独立、可审核的管理员设置步骤，Runner本身始终普通用户执行。只允许新建本项目专用镜像，拒绝已有路径、重解析点及任意调用方指定设备；初始化必须绑定新建镜像返回的设备身份，不接受用户提供磁盘编号，不处理已有物理分区。挂载不存在、身份/容量/文件系统不符时拒绝实验。重启后的重新挂载也可能需要管理员步骤，不承诺只提权一次。

用户已接受这项部署条件和固定空间占用。先实现只针对新建镜像的准备/核验工具，再实际验证Home能力、挂载路径与PSEC最终卷路径、卷满拒绝、重启/断开恢复、全树回收和镜像卸载；这些未通过前仍不能开放真实代码。虚拟磁盘是容量边界，不替代PSEC读写隔离，也不解决模型外发或所有内核漏洞。

## 来源与排除方案

- [微软 About VHD](https://learn.microsoft.com/en-us/windows/win32/vstor/about-vhd)：原生API可独立于其他虚拟化技术使用，无需为此安装Windows Sandbox；固定磁盘预分配最大请求容量。当前Home机器的实际成功仍待验证。
- [微软 AttachVirtualDisk](https://learn.microsoft.com/en-us/windows/win32/api/virtdisk/nf-virtdisk-attachvirtualdisk)：挂载要求SE_MANAGE_VOLUME_PRIVILEGE。本轮不提升Runner、不改系统特权。
- [微软 Disk Quota Limits](https://learn.microsoft.com/en-us/windows/win32/fileio/disk-quota-limits)：NTFS配额按文件所有者计费且不计部分元数据；不能未经论证就把现有用户/卷配额当成每个实验目录配额。本轮不改变用户现有磁盘配额。

## 仍独立存在的门禁

CPU/总内存行为、宿主链接/竞争处理、模型外发授权、正式远端IPv4和子进程攻击覆盖继续保留；IPv6仍按用户决定不探索。接受本候选不等于接受P1，不降低REQ-034。

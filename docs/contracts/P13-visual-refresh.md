# P13 前端视觉重构契约

依据：用户 2026-10-21 直接要求（“由另一个Agent编写的前端我仍旧不满意……自由发挥，优化前端内容……保存版本，因为我可能会回退版本”）、UI-Recommand.md 既有风格约束（蓝白、DeepSeek 风格、简约不花哨）、REQ-055/057/059–062。本轮只做表现层重构，不改业务语义。完整记录见 TURN-20261021-001。

## 目标与原则

- 蓝白极简、留白充分、层级清楚，向 DeepSeek 的克制风格靠拢；不使用动画炫技、不引入第三方 UI 库或新 NuGet 依赖。
- 只改 WPF XAML、样式资源、代码后置的视觉构建、ReaderAssets/reader.css、主题化确认弹窗；业务服务、DTO、数据库 schema、授权/预算/安全边界一律不改。
- 既有 AutomationId、控件 x:Name、事件处理器与桌面检查依赖保持可用；不得用视觉重构削弱任何自动断言。
- 视觉与信息架构可自由发挥，但既有流程顺序、按钮语义、二次确认与“取消不写库”等行为必须保持。

## 兼容与边界

- 历史 1.4.1 正式包、标签、验收证据与用户真实课程库原地保留；本轮不启动、不读取、不写入，任何验证只用独立合成库。
- 不做收费 API、OCR、生成代码执行、远端推送；阅读器与答疑的安全策略（CSP、主机对象、导航拦截、密钥不落界面）不放松。
- 阅读器 CSS 仅样式；不改 reader.js 的渲染与校验逻辑，不改 Quiz 判分、选项乱序与选项 ID。
- 视觉可自由发挥，但不得以减少功能、隐藏关键授权信息、跳过二次确认为代价。
- 自动检查只证明行为不回归；审美与偏好由用户人工验收，人工签收独立记录。

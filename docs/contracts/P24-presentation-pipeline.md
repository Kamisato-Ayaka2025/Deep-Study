# P24 PPT流水扫描契约

对应REQ-089，覆盖P23历史20页批次/4并发的PPT部分；PDF不变。

- UI默认8，可选16；当前会话有效，扫描时锁定，暂停后可切换。不改变配置密钥或现有课程数据。
- 生产者一次校验source fingerprint、一次打开受控PowerPoint副本；每页导出后直接发布，整个扫描只有一个STA渲染者。不持有知识库mutex等待生产，以免阻塞识别保存。
- 队列最多4张待处理页图，消费者最多8/16个；保留4MiB单页上限，页图授权hash验证、页序/集合/fingerprint校验，不能将整套页图装入内存。已发布PNG临时文件即时删除，图像字节交由队列与消费者持有。未识别的预渲染页不跨进程缓存；已完成识别页仍永久复用。
- 每个消费者独立复用OcrService已有单页授权、当前模型检查、三次临时错误重试、300秒时限、输出规格和迟到结果拒绝。启动一次能力检查，不逐页重新查询能力。
- 每页先StageOcr持久化，再计进度；每20个完成页提交不可变索引。暂存与提交串行，避免并行重建/删除暂存竞争。结束或取消等待生产者与消费者退出，再提交不足20页的剩余结果；重启先恢复暂存。
- 任一终止错误停止生产与新派发，取消在途可取消请求，已完成页保持；用户取消不把迟到回复算完成。PowerPoint当前同步COM操作返回后才响应取消，不强杀用户进程。
- 保留已冻结引用、原生正文与视觉合并、原文件只读、禁宏/外链清理；无schema或数据库迁移，渲染身份与提取版本不变。
- 本轮仅阶段一，不减内容、不换模型、不引入多图合批或本地OCR。对照测试固定模拟延迟+真实渲染，不能当作实际网络倍数保证。
